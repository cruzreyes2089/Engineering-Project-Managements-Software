# Whole-project effort and provisional forecast — REP-01 / PRJ-02

The existing operational date-range report is unchanged: overlapping full task estimates and period time are different scopes. New read-only project effort review uses all dates and current task estimates, grouped by task in one SQLite snapshot with Reports.Operations plus existing project-view requirement. No rates, compensation, invoices or expense amounts. Bound 500 tasks. Approved time excludes invalidations; pending, rejected, invalidated distinct; overhead and expenses excluded. Cancelled/discontinued task estimates excluded from current plan, but their approved and pending time retained as separate historical effort. Current estimates are not a frozen original contract baseline; proposed/held scope can be included in the current plan. No inference of authorization, physical progress or cost.

Optional temporary task-level remaining unsubmitted minutes, explicit zero allowed; exactly one per currently open task for complete forecast. Duplicate, closed, unknown or invalid input rejected. Provisional current-scope total = current approved + current pending (assumed accepted) + entered remaining; total including historical effort adds historical approved and pending. Rejected/invalidated records excluded from forecast; completed/cancelled/discontinued tasks assumed no further work in this scenario. Pending facts are not approvals. Incomplete open inputs yield no total or variance. Snapshot re-read and structural equality before calculation detects changed task/time totals; not a persisted approved forecast or immutable evidence, and changes after read remain possible. Refresh discards assumptions. No schema change, billing, automatic rescheduling or production release. Tests include exact classification, incomplete/complete forecast, service grants and reconciliation; Windows and interactive qualification pending.

The current candidate additionally binds a project-local source evidence digest, covering complete phase/task rows, cancellations/discontinuations and raw time submissions/reviews/invalidations in the same read transaction. Expense and overhead facts are excluded. Stale checks compare the digest as well as the displayed task totals. Maximum 100000 evidence rows and 128 MiB serialized values; exceeding limits fails rather than truncating. The digest does not authenticate historical records or constitute an independent checkpoint; no raw evidence is exported. Tests cover actual time submission, review and exclusion of expenses. Native verification pending.
