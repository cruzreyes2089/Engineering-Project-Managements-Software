# Due-date aging calculation foundation

Pure, offline calculation from a bounded complete balance observation and explicitly supplied due-date observations bound to the exact invoice ID, reference, customer, issue date and acquisition timestamp. No default terms, invoice-draft due date or issue-date age is substituted. Balances split into future-issued, unknown due date, not yet due, due today, and overdue 1–30/31–60/61–90/91+; all buckets reconcile. Paid invoices are excluded. Missing evidence is a separate balance, not zero days overdue. Due before issue is unsupported pending provider qualification. Evaluation date is not a historical balance date. This foundation is not wired to UI or reminders because the actual Manager API date contract remains unqualified. Caller-supplied evidence is not authenticated by the calculator; the future adapter must obtain it during the same verified acquisition. No production posting, reminders or executable distribution.
