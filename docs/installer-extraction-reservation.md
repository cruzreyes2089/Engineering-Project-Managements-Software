# Protected installer extraction reservation (validation only)

Baseline PR #84: Windows 2702 native checks and 168 Python tests passed, zero warnings/errors. Synthetic prior upgrade and automated source security passed; DAO qualification failed.

The reservation requires an existing protected dedicated staging parent, creates a fixed child reservation, creates a non-overwriting exclusive lock, binds a unique identity to reviewed evidence, and creates an empty protected envelope. Seal validates the exact envelope then writes a durable review witness. Subsequent review rechecks ownership evidence, the lock handle ACL, exact root census, and envelope bytes. Disposal retains all evidence. A leftover or competing reservation is refused; no automatic retry, adoption or cleanup. The test fixture can populate the envelope with nonexecutable text only. The reservation is not a cross-process transfer protocol, a race-proof filesystem identity guarantee, Authenticode verification or release authorization. No package execution, actual NSIS handoff, production data access, or distribution. An incomplete seal can be corrected within the original live reservation; a released reservation cannot be reopened by this API. A reviewed recovery/cleanup procedure and trusted extraction parent provisioning remain outstanding.
