# Recovery copy (schema 21)

Administrator-only by default. Creates a new confidential SQLite file using the SQLite backup API, not filesystem copying of a live database. Committed records, documents, audit history, passwords hashes and accounting reconciliation history are retained. In the copy only, accounting profiles are deleted with secure_delete enabled, the database is compacted, and a sticky Restore lifecycle hold is inserted if no earlier hold exists. Source credentials and lifecycle state are unchanged. Integrity and foreign-key checks must pass; SHA-256 and byte count are returned. Existing files cannot be overwritten. A prepared audit entry is not a guarantee that filesystem publication succeeded. The copy is not encrypted by this feature, not a portable login token, and not a complete backup of Manager.io or the separate witness directory. Keep it in access-controlled encrypted storage, retain the hash separately, and do not upload it to GitHub. Restore and accounting re-enrollment require a separately reviewed procedure. No live restore or production dispatch is implemented. Test on synthetic data only.
