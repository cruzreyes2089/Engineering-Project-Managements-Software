# Historical project source mapping and conversion

Development-only offline layer. This is not a DAO extractor, import approval or proof of source authenticity. No actual source names or project records belong in the public repository.

1. Retain the trusted closed Access copy and exact metadata inventory hash. Qualify the CRM mapping against that same inventory. Create a private project mapping with format CRC-Access-Historical-Project-Mapping-v1, lowercase sourceSha256, inventorySha256, crmMappingSha256, and projects: {table, fields}. Map all eight historical targets to exact inventoried columns and transforms. IDs use integer-id or text-id, preserving the CRM parent conversion. Number, title and both historical status fields require text; optional site and authorizationEvidenceRef can use explicit blank with null column. Numeric/Boolean status codes, missing required fields and ambiguous/nondeclared relationships are rejected for separate review. The project ID must be nonnullable and uniquely indexed.
2. Run python tools/migration/prepare_historical_project_plan.py INVENTORY CRM_MAPPING PROJECT_MAPPING PLAN using private paths outside checkout. The plan reports exact projection and identity-only columns, binds mapping hashes, and grants no import authority.
3. In a separately qualified source extraction procedure collect the full raw projection and a separate identity-only census (not derived from the projection). Their JSON envelopes are exactly format, sourceSha256, planSha256, rows. Formats CRC-Access-Historical-Project-Projection-v1 and CRC-Access-Historical-Project-Identity-Census-v1 respectively. Rows contain the original column names and only the selected columns (identity census contains only ID, client ID, historical number). Keep raw bytes and independently record digests. Integer IDs must be JSON integers, never booleans or floats. Text is retained verbatim; optional null source semantics need explicit review, not silent conversion.
4. Run python tools/migration/convert_historical_project_rows.py INVENTORY CRM_MAPPING PROJECT_MAPPING PLAN PROJECTION INDEPENDENT_CENSUS CRM_TRANSFER PROJECT_OUTPUT CENSUS_OUTPUT --expected-plan-sha256 HASH --expected-projection-sha256 HASH --expected-identity-census-sha256 HASH --expected-crm-transfer-sha256 HASH. Use new private output files. The converter revalidates metadata and plan, checks exact input digests, preserves original IDs and labels, reconciles project identities/parents/numbers against the separately supplied census, binds output bytes to the reviewed CRM transfer and runs the existing historical preflight. Reported counts and hashes contain no row values. Neither output permits native project creation, work authorization, financial migration or live import.

The tool cannot establish that the census was actually collected independently, that the raw rows are authentic, or that nonidentity values exactly match the Access source. Actual DAO projection and independent census collection, manual field-value reconciliation, clean-machine desktop acceptance and real migration authorization remain separate gates. The raw envelope contract is a future extractor target; no extraction is claimed. Tests use synthetic metadata and rows only.

## Synthetic DAO extraction candidate

The Windows read-only extractor now implements the raw envelope contract for separately run Rows and Identity projections. It requires an exact reviewed plan digest, closed synthetic source confirmation, local nonlinked table/column metadata, bounded scalar types, protected distinct output paths and matching before/after source hash. It never performs native imports. The optional historical fixture extends the existing synthetic CRM generator without changing its default behavior. The new opt-in qualification creates and removes its own synthetic fixture and checks projected field scope, all normalized historical values, duplicate numbers, inactive parents, independent census, no overwrite, stale source/plan refusal and lock sentinel refusal. Run only with the existing trusted installed matching Access DAO engine: python tools/migration/qualify_synthetic_historical_projects.py --confirm-synthetic --dao-bitness 64 (or 32 as applicable). CI parses PowerShell and runs offline/native regression; actual DAO execution has not been verified. The synthetic expected CRM transfer is known fixture data, not evidence of actual CRM extraction. The extractor is not authorized for real Access data. No production release or migration scope change.
