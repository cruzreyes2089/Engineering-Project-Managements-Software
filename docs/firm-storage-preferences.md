# Business-specific storage preferences — schema 48 development

Each independent single-firm database has its own optional production and restricted storage roots. No CRC-specific path is seeded. Administrators with Documents.Restricted can access Staff and permissions > Business storage, save or edit the proposed roots with confirmation, and load them into the project-specific storage review. Exact revision checks reject stale saves, identical saves are no-ops, and immutable revision rows plus audit events retain changes. Existing projects and document records are not modified. Upgrade from schema 47 starts with no configured preference. Recovery copies preserve the private preference history as inactive metadata. The normal migration/restore schema target advances to 48.

The current scope is one firm per database, not simultaneous multi-tenant hosting. The strict local drive-letter lexical policy remains; network/share/cloud integration, actual drive and ACL checks, verified storage registration and project-to-storage-version bindings are not implemented. Saved preferences are not active roots; changing them does not migrate, relocate, overwrite, delete, adopt or create any folders. Future active storage changes require an explicit reviewed migration or per-project binding. Folder labels remain the current default template; configurable per-business folder templates are a distinct feature. No MEP subfolders; no production provisioning, accounting, main merge or release. All tests are synthetic; exact revision compilation and regression pending.
