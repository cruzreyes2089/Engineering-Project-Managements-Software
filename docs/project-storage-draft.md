# Proposed project storage locations — development UI

The Projects > Project documents > Project folders window now includes an administrator-only Review storage locations action. This is a temporary draft, not a registration. The service requires administrator role and grant, document/project/client views and restricted document grant. It rebuilds the current project plan, validates conservative Windows drive-letter path syntax, rejects root drives, UNC/device/relative paths, alternate streams, ambiguous components, reserved device names, short-name syntax, duplicate and nested roots, and long planned paths. The result binds exact roots and project plan in a digest. The UI shows the planned counts and clears the draft on edit or close. No paths are saved, inspected, enumerated, used to create files, or sent outside the application.

The draft is deliberately useful without enabling external filesystem side effects. Lexical acceptance does NOT establish drive type, local disk versus mapped drive, existence, alias/reparse identity, root ownership, OS permissions, separation of effective access, conflict with app data, or approval to provision. The restricted root must remain distinct from production; application grants alone cannot prevent a Windows user from opening an external folder. Actual storage registration, verified identities, owner-approved root selection, effective Windows access qualification, durable audit and provisioning are later gates. The 180-character root and 240-character planned path caps are conservative design defaults, not operating system limits. No database schema change; no MEP subdirectories. Source tests pending exact-revision CI. No release approval.
