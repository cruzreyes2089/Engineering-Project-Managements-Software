# Recovery staging confidentiality — schema 47 candidate

Recovery creation previously staged an unsanitized SQLite backup directly in the selected destination directory. Isolated restore likewise staged raw source bytes directly in the destination folder. Both now create an application-owned unique same-volume staging directory using the restricted workspace ACL policy. On Windows, final staging files receive an explicit protected DACL for current Windows identity, SYSTEM and local administrators before no-overwrite publication. The destination file DACL is checked after publication; if verification fails, no successful result is returned, and the published file is retained for manual review rather than silently deleted. This does not establish that all possible SQLite temporary files, system paging or dumps are contained. No change to source ACL, pre-existing destinations or live database. The recovery hash still covers bytes, not permissions or encryption.

Cleanup deletes only the fixed application-owned staging file and named SQLite sidecars, rejects unexpected directory/reparse entries and removes the empty staging directory without recursion. Unexpected contents or permission failures require manual review. No guarantee of cleanup on process termination or power loss; residual private staging must be reviewed, not blindly deleted. Directory and file checks are point-in-time; no hardlink, adversarial parent, inherited delete-right, effective access or concurrent manipulation guarantees. The destination parent may still be unsuitable for confidential data; actual protected encrypted destination and recovery custody remain operator/security qualification requirements. Do not assume moving or copying the file to other media preserves ACLs. Windows file permissions are not encryption. Non-Windows code is development-only. Tests check exact bytes and original recovery rules, final file ACLs and cleanup after successful and failed operations. CI pending; no real data, production activation, or executable distribution.

## Milestone 08 follow-up
Recovery creation now binds its copied-image and live-source authorization checks to the initiating login generation, matching isolated restore's existing generation check. Staging directories are explicitly verified after creation before any raw data is written, and again at publication. Synthetic tests check the pre-write Windows ACL and preservation of a destination that appears after staging. These are point-in-time checks; concurrent revocation after the final authorization check, filesystem manipulation, physical durability, and encrypted custody are not qualified. Exact-head CI and independent review remain required.
