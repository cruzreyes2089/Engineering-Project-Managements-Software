# Offline candidate wire contract

Owner-assisted API2 feasibility on Manager Desktop 26.11.11 validated the one-line sales invoice, allocated customer receipt and direct expense payment forms. This compiler models exactly those observed writable field names, not a general API specification. Quantity is fixed at one; no tax, project, discounts, purchase invoices, credits or multi-currency support. Synthetic USD is bound in the local hash and is not emitted as an unverified API property. The operation-derived reference format is proposed, not yet accepted by Manager. Description text is fixed synthetic text. No URLs, transport, credentials or POST execution exist.

Separate versioned wire hash binds the complete emitted JSON, operation, marker, kind and synthetic currency. It is not compatible with legacy rehearsal hashes (which lack receipt bank and other wire fields). Recovery review uses the full candidate wire fingerprint; actual provider readback must reconstruct an independently validated normalized fingerprint, not echo the local target hash. This requires exact field/date/reference and semantic readback evidence plus durable approved operational intent storage. No promotion of rehearsal rows into real postings. No authorization or binary distribution.

Automated candidate tests cover fields/types, stable references, decimal scale, identity collisions, missing or inappropriate relationships, changed bank/allocation/vendor/date/marker and unsupported currency. Actual write behavior remains confined to the already accepted PowerShell sandbox experiment. Existing security hold unchanged.
