# Project document usability

Document register now has a file-name search, immediately applied current-version filter, selection-dependent add/version/save-copy actions, and selected-document hash detail instead of a wide hash column. Each search reacquires the authorized bounded register; no client-side search of stale restricted records. Choose a file first, then access and category, and confirm save; replacement inherits prior metadata. Ordinary production remains the default, with explicit warning when choosing production for contracts. No automatic restricted classification, file execution, filesystem folder creation, overwrite, deletion or new document types. Existing server-side permission and identity checks unchanged. The UI does not constitute a security boundary. Prior project workspace receives exact-ID access and refreshed-state regression tests. Exact revision CI and interactive desktop acceptance pending; schema unchanged.
