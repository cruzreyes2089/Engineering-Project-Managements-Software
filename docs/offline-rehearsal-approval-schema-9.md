# Explicit offline rehearsal approval — schema 9

Source-only synthetic feature, no network writes or actual accounting approval. Adds a separate Administrator-seeded Accounting.Posting.RehearseApprove grant and an immutable local approval row for the existing reservation. The approval is tied to the journal row, marker and payload fingerprint. Immediate SQLite transactions serialize approval, dispatch and lifecycle checks. Begin fails closed if the approval is absent, invalid or the approver's current grant/account status is no longer eligible. No old reservation is automatically approved. Confirmed, cancelled, in-flight and uncertain histories remain unchanged; no reset or automatic recovery. Cancellation of an unsent reservation consumes the original operation key.

Same-actor approval is permitted only for the offline synthetic single-owner fixture.
