# Financial correction reference model

A bounded offline event replay validates synthetic accrual invoices, refundable unearned deposits, direct receipts, credits against open receivables, deposit applications and unapplied refunds. Corrections retain the original event and reference it with a unique full-amount reversal. Scope, date order, document identity, individual invoice and advance balances, intermediate nonnegative balances and independent final summary must reconcile. A second reversal, cross-customer/project correction, unknown original, partial reversal and reversal-of-reversal are rejected. Reversing a credit restores income/AR; reversing receipt restores AR and reduces cash; reversing application restores AR and deposit liability without cash; reversing refund restores cash and liability.

This is an in-memory validation candidate, not a durable append-only database journal or an actual Manager credit/refund contract. Inputs are caller-provided. Invoice voids, overpaid invoice credits/refunds, partial corrections, tax, earned-on-receipt retainers, expenses, opening balances and actual bank reconciliation remain outside this deliberately limited model. No production mutation, posting, paid status or reversal authority. FIN-03/06/07 remain open pending qualified provider behavior and approved accounting treatment. Schema unchanged; new regression pending.
