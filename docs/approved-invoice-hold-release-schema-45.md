# Independently reviewed approved invoice hold release — proposed schema 45

Dependent on schema 44 candidate 7159a88. Release is narrowly scoped to a demonstrably correct original internal draft with independent documented verification of no external issuance, settlement, or pending/uncertain accounting action. No automated inference from absence in API results. Do not release an incorrect or potentially issued invoice merely because the discrepancy has been noted. Manager remains authoritative. No credit, reversal, posting, collection status or cap changes.

- Migrate schema 44 holds into append-only per-draft event history, preserving actor, timestamp, reason and exact payload hash. New Hold and Release events alternate; bind each to exact prior event (first hold has none). Current hold state derives only from latest event. Re-hold permitted after release; stale release cannot remove a newer hold. Legacy original holds retained as archive with no further insert/update/delete. DB guards protect immutable lineage, event order, exact approved payload, authorization separation, and export guards use current hold projection.
- Release requires existing invoice edit/approve/view and project/client view grants; distinct actor from current hold author, draft creator and original approver. No owner exception for release. Require evidence reference and reason, separate attestations that original draft is correct and complete independent review confirms no issuance, settlement or uncertainty in external accounting including off-system records. Store evidence reference, review reason and reviewer identity, not a claim of automated verification. Exact current hold ID and payload required; atomic immediate transaction/audit. Single-owner firm needs a legitimately independent authorized reviewer or hold remains. No user should share credentials or create a nominal reviewer account for self-approval.
- Effective held subset in reports and export/byte retrieval restrictions follows latest event. Releasing restores only approved internal preparation, never makes an issued invoice or alters amount, lines, source allocation, cost, AR or cap. Historical metadata and all decisions retained. UI displays entire history, evidence and explicit release/renewed hold controls. Issued/uncertain/incorrect cases stay held pending provider reconciliation. Previously exported files cannot be recalled.
- Test-first stubs intentionally fail. Add independent permission, stale revision, concurrent/rollback, direct SQL, migration/restore tests; full Windows regression and desktop acceptance before promotion. No production data, main merge, provider mutation or distribution.

Candidate implementation: immutable alternating events, schema-44 migration and frozen archive, effective hold projection, explicit independent release attestations and evidence, renewed hold protection, reporting and export guards. Race, rollback and SQL regressions added. Database cannot prove off-system evidence is truthful; review remains operator responsibility. No external writes or accounting changes. Windows and desktop acceptance pending.
