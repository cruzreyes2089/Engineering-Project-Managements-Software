# Credential and session hardening (schema 47 candidate)

Existing PBKDF2-SHA256 uses 600000 iterations, 16 random salt bytes, 32 derived bytes and fixed-time comparison. Preserve exact existing encoding and iteration count; bound persisted text length and format before decoding, decode into fixed-size buffers, require canonical base64, reject malformed/null inputs, clear derived and decoded buffers. The immutable .NET password and encoding strings cannot be guaranteed wiped; no claim of process-memory confidentiality. The application still uses Windows DPAPI CurrentUser for Manager credentials, not whole-database encryption. Same Windows user/process access and offline SQLite reads are outside domain role enforcement. No change to remote credential acquisition, API, accounting or schema.

FirmName previously returned firm identity without checking an authenticated session. Require valid current session, active account, no required password change and matching credential revision; no extra domain permission needed for legitimate staff firm identity. Domain grants continue to be checked transactionally. Expire sessions at the existing eight-hour limit using both UTC deadline and elapsed Stopwatch time, so wall-clock rollback alone cannot extend a session; fresh login resets both. Logout clears the session timestamp. This does not establish system suspend behavior, idle timeout, concurrency-safe session mutation or revocation of already rendered UI data. Desktop cache and modal lifetime are separate follow-up. Regression methods cover compatibility, malformed hashes, salt uniqueness, expired sessions, firm identity and staff revocation. Synthetic reflection sets only the test instance clock fields, not machine time. No production activation, key material or binary distribution. Windows verification pending.
