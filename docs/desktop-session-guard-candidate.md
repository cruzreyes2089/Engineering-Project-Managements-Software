# Desktop session guard — schema 47 candidate

Proposed development default: 15 minutes of elapsed inactivity and existing eight-hour absolute maximum. The persistence service checks both before authorized operations; only explicit desktop key/button/wheel/touch input refreshes activity, not a timer or background service call. No reactivation of expired sessions through input. A five-second WPF dispatcher timer and activation check compare a transactional stamp of current authenticated identity, credential revision, role and effective allowed grants. Any observed change or verification error locks the whole desktop workspace rather than leaving stale permission-dependent views open. Transient grant changes between polls can be missed; transaction-level Require remains authoritative. No guarantee for a blocked UI dispatcher, sleep/resume behavior, native file/message dialogs, screen capture, clipboard history or already exported files.

Lock first invalidates the service and its generation, clears main CRM rows/search/selection/company labels and password fields, disables and closes owned WPF windows recursively, and requires reauthentication. A close failure requires restart. Main Run tracks modal operation depth and prevents signing in while an old synchronous operation is still unwinding. On next login a fresh LocalPractice instance is created; old asynchronous windows retain their logged-out service, not the new session. Existing async cancellation/revision guards remain; cannot cancel already completed operations or guarantee all external requests stop immediately. No whole-process memory wiping or proof that every cached object is collected. No production startup or data access enabled. This is a development default, subject to owner approval.

Native tests cover idle expiration, nonrenewing read, explicit activity, grant stamp change and reset invalidation. Interactive WPF verification remains required: idle and absolute timeout while dashboard, CRM and nested modal are open; permission grant/revoke, account reset/deactivation, stale async response, close failures, native dialog interruption, reauthentication, no new session access by prior window. All pending independent exact-artifact approval. Whole SQLite database still plaintext; DPAPI protects only Manager credentials. Production confidentiality requires independent review of OS account ACLs, encrypted storage/backup and recovery/key custody. No encryption provider selected or dependency changed.
