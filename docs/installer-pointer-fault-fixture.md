# Disposable text staging and activation pointer fault fixture

This source-only test fixture creates its own temporary directory, fixed non-executable text markers and a separate synthetic SQLite review journal. No external path, application payload, real database, installer, user data or startup configuration is accepted. It does not select or launch the application. It uses an in-process lock, exclusive creation, file flush/fsync and same-directory os.replace of fixed text markers. The journal supplies an exact independently retained checkpoint (retained in the test process), and the actual text observations are fed into the existing model. Synthetic data and recovery bytes remain unchanged. No acceptance is inferred from a pointer change.

Fault scenarios: partial staging, interruption after pending marker creation, interruption after pointer replacement but before journal update, injected replacement denial, modified staging/data/recovery, stale checkpoint, unrecognized pointer, unexpected staging files and hardlinks. A pending marker blocks further action; an observed completed switch can be recorded only with the exact switch-intent checkpoint, not repeated or reversed. Tests do not implement cross-process installer locking, physical disk-full or power loss, Windows directory durability, reparse race resistance, independent persisted checkpoint custody or actual code installation. The hardlink subcase may skip on unsupported filesystems. Synthetic fixture cleanup is confined to its own temporary directory.
