# v0.4.6 — provisional local customer links

Live API2 exposes business.name only. Vendor describes tokens as per-business, not immutable business identifiers. Links are therefore sandbox-only, explicitly selected, one-to-one per CRC user and saved profile revision, guarded by exact observed business name. They are not production mappings. No automatic name matching. A fresh customer page and current active client are required to save, and permissions/session/profile are rechecked before committing. Profile replacement/removal invalidates old scopes; prior rows remain local and inaccessible through the new profile. User must manually recreate links; no automatic revalidation/transfer. This does not detect cloned businesses sharing credentials/IDs, or business renames reversed between reads. Identity verification, cross-user mappings, cleanup/revalidation workflow and all posting remain separate gates. Unlink only deletes the exact selected local association. Link/unlink audited. No Manager writes.

Schema 4 adds dedicated Accounting.Customers.Map permission (administrator initially), scope and link tables; preserves existing schema 3 credentials and CRM. Back up closed development database before upgrade. Older builds cannot open schema 4. Use synthetic data only. Automated checks plus owner verification required.
