# Offline CRM mapping preflight

Source-only tool: tools/migration/validate_crm_mapping.py. It checks an explicitly reviewed mapping against the metadata-only Access inventory. It never opens Access, reads records, creates a transfer or authorizes import. No private schema or row data in the public repo.

Mapping JSON root has exactly format (CRC-Access-CRM-Mapping-v1), inventorySha256 (lowercase SHA-256 of exact inventory file bytes), sourceSha256 (exact value in inventory), clients and contacts. Each entity has table (exact local table name) and fields (exact normalized transfer target names as listed in legacy-crm-transfer-schema-27.md). Each field rule contains column (exact source field name or null) and transform. Allowed transforms: text (DAO text/memo), text-id or integer-id (explicit ID conversion), boolean (DAO Yes/No), reviewed-enum (reviewed type/status translation required before extraction), blank (explicit omission of optional target only). No inferred field mapping, numeric ZIP formatting, default enum values, credentials, or row conversion. Both ID fields require a unique single-column nonnullable key; exact declared single-field parent relation required; schemas without it need separate human review. Actual values, case-insensitive ID uniqueness, orphans, primary flags, name presence, enum translations and financial data remain unverified. A successful preflight is a metadata check only.

Run locally with trusted Python 3: python tools/migration/validate_crm_mapping.py PATH_TO_INVENTORY.json PATH_TO_MAPPING.json . Both files stay local. Review source SHA and mapping independently before extraction; no actual user schema or records are available yet. Synthetic unit tests cover valid metadata and rejected mismatches. Windows CI pending; separate DAO acceptance and data reconciliation required.
