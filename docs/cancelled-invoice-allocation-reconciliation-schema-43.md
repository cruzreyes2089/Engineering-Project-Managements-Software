# Cancelled invoice allocation reconciliation — proposed schema 43

Dependent on schema 42 candidate 3db75f3. Scope is an erroneous approved work fact previously allocated exclusively to cancelled internal drafts. Approved drafts can be exported for manual accounting preparation and may already correspond to real invoices; never infer that they are unsent or safe to reverse. No external accounting mutation, credit note, payment reversal, or issuance status change.

- Explicit allocation review restricted to correction and invoice review/edit grants. Project and source identity, all allocation draft IDs, immutable payload hashes, state and amount in deterministic order; verify each draft's integrity. Eligibility only for a currently approved, noninvalidated source with at least one allocation and every allocation cancelled before approval/export. Existing ordinary invalidation remains blocked for any allocation. Bind review to canonical evidence hash; re-read under immediate transaction, reject stale or changed evidence. No self-invalidation. Require actual factual error, explicit confirmation, evidence, exact current closure ID if closed. All approved/live/uncertain drafts remain blocked. Cancellation in this system only proves internal status; operator must verify no external invoice exists, including manual off-system issuance.
- Atomically record immutable reconciliation evidence and invalidation; preserve all draft lines, decisions, hashes and original fact/approval/classification. No new draft, credit, settlement or payroll transaction. Exclude erroneous fact from effective cost and billing candidates. Permit one linked replacement through existing active/closed correction route, fresh independent review and classification; historical allocation allowed only with validated reconciliation evidence. No release of approved allocations. Avoid a duplicate AR ledger.
- UI restricted to authorized reviewer; show exact draft register, explicit operator attestation and stale review guard. Database enforces cancellation-only policy, immutable evidence, source identity and prior allocation protection. Add rollback/concurrency/SQL/migration/restore tests. Test-first stubs intentionally fail. Full green Windows required before promotion.
- Approved draft and provider-side reconciliation remain separate. No production data, main merge or executable distribution.

Candidate implementation stores the immutable allocation review fingerprint on the existing invalidation evidence; source-linked immutable draft history reconstructs the reviewed allocation list. Service verifies exact payloads and complete review hash under one write transaction; SQL enforces all cancelled, no generated review document or recorded manual export, and prior allocation only through explicit invalidation evidence. SQL cannot independently verify SHA256 or off-system issuance; operator attestation remains necessary. Existing draft and cost projections are preserved, no provider writes.
