# Synthetic physical folder provisioning qualification

The current application remains preview-only, schema 47, with no physical folder command or storage registration. Revision CRC-Production-2 has nine flat production folders, optional correspondence, no automatic or optional MEP subdirectories, and a separate logical restricted administration boundary.

The ordinary native smoke suite now exercises a physical provisioning candidate in an owned, disposable synthetic workspace. The candidate derives all entries from the current fixed template and project identity, checks root ancestors and target directories for reparse points and non-directory collisions, and binds the exact logical plan, separate synthetic roots and observed existing/missing state into a review fingerprint. A new review is necessary after any selection or observed state change. Explicit confirmation is required. It creates missing directories only, never overwrites or removes files, never moves records and verifies the resulting directory state. An interruption is treated as incomplete, not rolled back by deleting folders; a fresh review can safely repair missing directories in the fixture. The smoke suite checks stale reviews, wrong-project replay, existing files, collision rejection, interrupted creation, idempotent replay, optional correspondence, separate roots and absence of MEP children. Real symlink denial is checked only if the environment permits creating a synthetic symlink; otherwise it is explicitly reported as unqualified.

The candidate is test-only, not a production path-validation or access-control solution. The test roots are created by the harness; they are not registered firm storage. The path checks cannot exclude hostile concurrent filesystem replacements, aliases/hard links or all Windows namespace edge cases; separate synthetic directories do not prove OS ACL separation. No credentials, actual firm storage, external folder adoption, network/share support, ACL configuration, application-level commit/audit journal, or release authorization. Before production integration, qualify Windows handle-based/no-follow filesystem operations or an appropriately protected exclusive storage boundary, validate actual ACLs and root identity, record reviewed template and durable attempt/outcome evidence, and verify recoverability after interrupted operations. Existing directories in real storage must not be adopted by this synthetic fixture behavior. Source tests pending exact-revision Windows CI.

## Durable synthetic operation journal

A separate SQLite journal in the test-owned workspace now commits an immutable intent before any folder creation and an immutable outcome only after verified completion. Missing outcome is Uncertain, never success; restart cannot silently retry. A fresh observed review, explicit confirmation and matching project/plan are required to supersede an uncertain attempt and create its linked repair. No rollback deletes physical directories. A lost acknowledgement after successful creation is reconciled by a zero-create repair, retaining both attempts. The synthetic test checks reopened uncertainty, stale/changed/wrong-project recovery refusal, interruption, lost acknowledgement and immutable evidence. SQLite synchronous FULL and a serialized transaction protect journal changes; no claim of atomicity between SQLite and the filesystem. This is a single-process synthetic candidate, not a production concurrency lock or authenticated audit log. Before activation qualify interprocess fencing, root/handle identity, ACLs, storage registration and recovery backup pairing. Native schema 47 and application preview-only behavior are unchanged. Exact-revision regression is pending.
