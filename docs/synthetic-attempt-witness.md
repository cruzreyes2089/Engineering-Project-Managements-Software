# External synthetic attempt witness

Development-only prototype, separate from the SQLite rehearsal journal. Records the operation and attempt GUIDs, marker, store identity, kind, proposed reference and full wire fingerprint in an exclusive-create file, with flush-to-disk requested. Existing, partial, unavailable or conflicting evidence is never replaced. The component has no send, retry, reset, deletion, live permission, database wiring or actual provider transport. Even a successful record grants no authority.

The caller must explicitly provision an empty, separately retained directory and preserve its scope identity outside both database backup/restore procedures. Recording never initializes a missing scope. The prototype rejects reparse points on the inspected path and uses bounded exact comparisons; this is not a hardened filesystem security boundary, atomic distributed lock, cryptographically authenticated witness, or proof of physical durability. Directory substitution, deletion, malicious tampering, copied witness and rollback of all stores remain possible. A missing witness must not be interpreted as proof that no send occurred. Tests model local cooperating-process races and retention across a new client, not actual backup/restore or power failure. Independent retention, ACLs, verified inventory and incident recovery require a deployment design before native writes. No binaries distributed.
