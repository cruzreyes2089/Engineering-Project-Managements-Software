# Project folder template — development preview

The current WPF Projects > Project documents workspace includes a Project folders preview action. This is a read-only view of a versioned relative template, not a registration, provisioning, filesystem validation or folder access grant. The preview identifies the selected native project using existing accepted-project and document view checks; it does not require an agreement or project start authorization because it writes nothing. Historical archive rows are not native project IDs and have no folder action.

Production template CRC-Production-2:
- Architectural

- Plancheck Comment Responses
- QA-QC
- Reference Documents
- Send Outs
- Site Pictures

Correspondence is optional and off by default. MEP reference files go directly into Reference Documents when needed. No MEP, Mechanical, Electrical or Plumbing subdirectories are generated by default or as an option. Existing Conditions and general Administration are not default production folders. Restricted administration is separate: Proposals, Agreements and Contracts, Change Orders and Additional Services, Billing Administration. The restricted branch is omitted from the service result when Documents.Restricted is absent; the UI is not the access-control boundary. No paths or folder names are supplied by user input.

The restricted labels are design defaults; the preview currently uses a fixed template revision and optional correspondence, not persisted customizable templates or per-project selections. Later provisioning must use explicit approved distinct roots, reparse-point checks, OS-level restricted ACL qualification, preview/confirmation, immutable template revision and audited outcomes, idempotent creation/repair and no move/delete/overwrite of existing files. Do not change the project setup completion or start status based on preview. No external directory creation, registration, actual file migration, security-hold change or release approval in this batch. Source tests cover approved labels, optional selection, permission revocation, separate project context and no document record creation. ## Revision 2 and logical provisioning plan

Owner requested removal of the complete MEP branch, including any optional creation. Revision 2 supersedes revision 1 without inspecting, moving, or deleting any existing folders. The fixed template now has nine flat production folders, or ten with optional correspondence. A deterministic relative plan uses the immutable native project number as the prospective directory name under each logical boundary; the exact name, project ID, template revision, option and permission-filtered entries are bound in a SHA-256 fingerprint for future stale-plan checks. A fingerprint is not an authorization or proof of filesystem security. Restricted logical entries are omitted at the service boundary without the restricted permission. Absolute roots, external folder registration, physical provisioning, ACL qualification and recovery remain unimplemented. Using native project number alone as the logical folder name is a design default, not a deployed storage policy. No schema migration or real file operation in this revision.
