# Desktop acceptance workspace — test-first specification

Separate opt-in synthetic workspace under LocalApplicationData, not a live database picker. No arguments preserves existing development path; --acceptance-new reserves a fresh UUID folder; --acceptance-session <32 lowercase hex UUID> opens only an existing initialized acceptance workspace with its exact marker. Reject unknown/malformed arguments without default fallback, never accept arbitrary file paths, check workspace reparse points, refuse missing/changed marker or database, and show acceptance ID in main title and status. No automatic deletion, no credentials or real data, no production accounting. This is protection against accidental workspace selection, not a security sandbox or malicious local administrator. Use a dedicated isolated Windows VM with network/real credentials unavailable for offline acceptance, only after security approval; do not run or distribute quarantined executable. Test-first stub deliberately fails; functional CI and interactive desktop acceptance distinct. No new database schema.
