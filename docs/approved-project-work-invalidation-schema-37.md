# Approved project work correction — proposed schema 37

Dependent on schema 36 candidate 83ea28a. This deliberately narrow workflow addresses demonstrably erroneous or duplicate approved project facts, not a reversal of actual work performed or an instruction to withhold wages or reimbursement. No external ledger, payroll or posted invoice changes.

- Add Work.Correct grant initially administrator-only, require Work.Review, Projects.View, Clients.View and Employees.View. Independent actor (not submitter, even founding owner exception does not permit self invalidation), explicit confirmation and documented reason. Only currently approved, uninvalidated fact on operationally active project, with no invoice line allocation ever (including cancelled draft). Preserve original fact, approval, classification and immutable invalidation evidence; record atomic audit. No retroactive edit/delete. Closed projects and prior allocations require separate reviewed reconciliation. 
- Effective state Invalidated exposed in own/reviewer history, separately counted in operational and firm time reports; excluded from current approved time/cost, daily cap, billable candidates, new classification and invoice source allocation. Never confuse invalidation with ordinary rejection. All report totals reconcile; historical submitted time and original approval evidence retained. Existing approved invoice lines and audit reports unchanged.
- Explicit employee linked replacement API for invalidated predecessor (distinct from rejected replacement); same ownership, assignment and kind, corrected actual facts, date limits, exact retry and one successor. Replacement starts Submitted, fresh approval and classification required; no automatic recognition or posting. Bind operation intent to source and replacement path; database guards prohibit invalid predecessors and stale billing allocations.
- UI correction action restricted to authorized independent reviewers, warning not for real earned time, no invoice allocation, explicit evidence, confirmation; employee correction selection displays effective state, lineage. Add race, rollback, direct SQL and migration/restore coverage. Do not change prior tests to weaken assertions.
- Overhead approved corrections, self-correction policy, closed project corrections, payroll/expense settlement, exported/posted invoice reconciliation and reversal remain deferred. No release distribution or production data.

Test-first stubs intentionally nonfunctional. Run red then green after schema 36 verification.
