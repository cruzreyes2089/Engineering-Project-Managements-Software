# Controlled legacy CRM transfer — schema 27

No actual Access database or client records were used. This is a deliberately narrow, one-time import from a reviewed UTF-8 JSON transfer with exact root fields format (CRC-Legacy-CRM-v1), clients, contacts. Client fields: legacyId, legacyNumber, type, company, first, last, email, phone, address1, address2, city, state, zip, notes, status. Contact fields: legacyId, legacyClientId, first, last, title, email, phone, primary (boolean). All other row values are strings, even empty optional fields. IDs are nonblank ASCII alphanumeric/dot/underscore/hyphen, case-insensitively unique within each entity. Type/status must match native enumerations. Text is trimmed and US phone formatting normalized by native validation. Orphans, duplicate IDs, duplicate primary contacts, unknown fields and invalid phones are rejected, not discarded. Duplicate client name/legacy number groups are reported and never merged. Historical contacts under inactive clients are retained. 10 MiB, 5,000 clients, 10,000 contacts maximum.

Administrator and separate migration/CRM grants required. Preview is read-only, exact raw file SHA-256, row counts, duplicate warnings, empty target check. Explicit confirmation, review note and revalidated same bytes/hash are required. Entire import, source ID/native ID mappings, new native numbers and audit history commit in one immediate SQLite transaction or roll back together. No financial records, staff, credentials, projects, agreements, attachments or direct Access mapping. Actual legacy schema and reconciliation remain unqualified; a trusted read-only source inventory and reviewed mapping are needed before any real import. No automatic file upload or executable distribution.

The post-import evidence screen and confidential CSV export show original client/contact IDs, original client numbers, native IDs and native client numbers; check mapped counts and parent links before displaying or exporting. Source hash is required for export. No contact names or financial values are exported in the mapping CSV. Mapping history does not claim current records are unchanged after later legitimate edits.
