# External folder and document transmittal register design

Native pure review models only; no schema expansion, durable register, folder browsing, or real issuance. Folder reference uses an explicitly reviewed, dedicated local root and existing relative directory, separated from database storage. Reject rooted paths, traversal, ambiguous components, drive roots, missing folders and reparse ancestors via LocalStoragePath. Overlap checks cover equal/nested lexical paths; not handle-level identity, junction race, short-name alias, ACL, encryption or shared/network storage qualification. No directory enumeration, opening, creation or automatic file transfer. Next persistence must store root revision and folder history, enforce unique non-overlapping assignments across projects in one transaction, and require explicit administrator permissions; actual sharing policy requires separate review.

Transmittal intent binds exact project, recipient, purpose and sorted unique reviewed PDF metadata. Four possible sequential events: Prepared, IssueRecorded, DeliveryRecorded and Withdrawn (withdrawal terminal; allowed from any recorded state). Recorded issue and delivery require explicit external evidence reference, note, actor and UTC; the model validates ordering and digest links, not the truth of external evidence or professional authorization. No automatic issue, send, signature, stamp or delivery. Withdrawal does not undo delivery. The application-facing persistence service must recheck document currentness, byte hashes, project/conflict/QA gates and actual approval at issue time; delivery is a historical attestation to an already recorded issue, even if documents later superseded. No invented authority or owner approval. Future durable schema must pair audits transactionally, protect historical metadata, reconcile recovery and qualify migrations. Native regression tests added for path and lifecycle invariants. Windows verification pending.
