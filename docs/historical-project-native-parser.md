# Native historical project package parser

Schema 46 remains unchanged. This is source-only Core validation; no SQLite migration, permission change, production import or WPF register. The parser takes the exact CRM transfer, project transfer, and independently collected project census bytes with separately retained lowercase SHA-256 values for each file and the source Access database. Each file is limited to 10 MiB and copied before verification. The CRM package passes existing native CRM parsing. The project and census formats match the earlier offline preflight; duplicate/unknown/missing JSON fields, malformed identifiers, orphan relationships, stale bindings, invalid control characters and mismatched original project numbers are rejected. Nonempty project batches up to 10,000 rows are required for this archive candidate.

The project identity census matches exact original project IDs, parent ID spelling and project number, independent of order. The native parser preserves historical source labels and whitespace without assigning a native lifecycle state. Text length is measured in Unicode scalar values. Duplicate number groups are advisory and use trimmed ordinal-ignore-case matching; Python preflight uses Unicode casefold, so unusual non-ASCII project numbers may produce different advisory counts. Inactive-client counts refer to the supplied CRM transfer, not later changes to native clients. Neither a supplied evidence reference nor a source-reported approval is verified authorization. The package's source-authenticity, historical-authorization, native-project-creation, work and financial-migration flags always remain false. It is not an import approval or a substitute for the actual DAO and field-value qualification.

## Proposed service contract (not implemented)

- Dedicated HistoricalProjects.View and Administration.HistoricalProjectImport grants, seeded to administrators only; require current active authenticated session and Clients.View for record access. Import additionally requires administration, explicit confirmation and both grants. Test revoked permissions and restricted projections independently of the UI.
- Preview must parse and bind exact source, CRM, transfer and census bytes, check existing sealed CRM mapping history against the CRM digest and resolve every parent through that mapping. Return counts, duplicate-number warning, and target status. Do not reserve operational numbers or create native project/engagement rows.
- Import must repeat validation inside the controlled write operation, use one immediate transaction for the archive batch, all rows, seal and audit event, and require a review note. Same exact package may return AlreadyImported only after checking sealed evidence and row integrity. Changed package or incomplete historical state must fail closed, not silently merge or repair.
- Restricted read-only register returns sealed archive records and explicit historical status labels. Do not expose evidence references to ordinary staff or resolve them as file paths. Do not embed archive records in active project selectors. A future reviewed association to an operational project is separate from start authorization, and must not bypass proposal/agreement/conflict gates.
- Preserve existing schema 46 until combined Windows source regression is verified. Schema migration, permissions, archive import, register UI and restore version support remain separate integration tasks.
