Dependent on schema 41 candidate a90c86e. Explicit historical correction for closed projects, not authorization for engineering work, a reopening, or a ledger reversal.

- Independently authorized Work.Correct/Work.Review and existing read grants; exact latest closure ID; explicit confirmation and evidence. Approved erroneous unallocated fact only, no self-invalidation, no prior invoice allocation including cancelled drafts, no duplicate decision. Record closure identity on immutable invalidation evidence, retain approval/classification. Existing active-project invalidation remains distinct.
- Employee-owned linked correction for rejected or invalidated source, same task/employee/kind and original work date (conservative closed-project policy; correcting date requires separate exception). Exact current closure, date within original task/cutoff, fresh confirmation/evidence, active employee, daily cap, single successor, immutable normalized replay and independent new review. No bypass of source allocation guard. Existing ordinary active-project replacement unchanged. Original approved or rejected evidence preserved.
- Closed and conflict-hold status unchanged. No payroll or accounting mutation; effective cost/billing projections use existing invalidation semantics. Pending corrections remain visible. UI explicitly separates ordinary vs closed corrections and shows exact closure identity. Migration, SQL guard, audit rollback and concurrent decision/replay tests.
- Closed date correction, historical facts for departed employees, prior invoice allocation reconciliation, payroll/settlement and external reversals remain separate. Test-first stubs deliberately fail; full Windows green before promotion. No main merge, production data or executable distribution.
