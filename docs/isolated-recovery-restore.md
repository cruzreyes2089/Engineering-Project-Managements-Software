# Isolated recovery restore

Requires authenticated administrator and recovery-copy grant, trusted separately recorded SHA-256, closed .db recovery copy (no sidecars), new .db destination, current schema 46, bounded 4 GiB copy, exact byte hash before SQLite opens, read-only integrity and foreign-key checks, isolation audit record, no accounting profiles, existing accounting lifecycle hold and owner exception disabled. Rechecks session and authorization before exclusive publication. Never replaces or points the app to a live database. No schema migration of older backups, recovery of external witness files or Manager backup, system-level restore, cryptographic proof of origin or full tamper resistance. The operator must retain backup hash and access-controlled storage; an attacker controlling the local filesystem or hash record is outside the protection model. A prepared audit entry does not prove filesystem publication. Synthetic tests only.
