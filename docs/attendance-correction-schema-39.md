# Attendance corrections — proposed schema 39

Dependent on schema 38 candidate 6123ae0. Attendance is a record of clock events, not billable time, payroll, approved work or capacity. No implicit work submission or wage adjustment.

- Independent manager correction under Work.Correct and Work.Review with existing employee/project/client read grants; no self correction, including owner exception. Exact session and expected latest correction ID, mandatory evidence and confirmation. Append-only revision containing corrected UTC interval, actor and timestamp; original clock-in and raw clock-out retained. Closed sessions and missed clock-out on existing open sessions only; missing entire sessions and duplicate/void corrections remain separate.
- Corrected interval must be UTC-second precise, nonfuture, nonreversed, and nonoverlapping with other effective sessions for same employee. Treat intervals half-open; allow zero-length existing clock intervals, but no point inside another interval. Prevent changes to raw clock-out after administrative recovery. Existing single-open and clock monotonicity controls must use effective state, not raw nullable clock-out. Database guards plus immediate transaction/audit; migration preserves raw records. No edits to project work or overhead data.
- Employee sees effective own interval and correction identifier, reviewer sees raw and effective timestamps and immutable correction history. Manager UI explicit UTC inputs and reason; no payroll inference. Date ranges use UTC and match either raw or effective intervals for manager history (employee effective only). Tests for permissions, stale revisions, overlap, future, missed clock-out recovery, concurrency, rollback, raw history and migration/restore.
- Test-first stubs intentionally fail. Require exact red then full green qualification before integration. No production data, external posting, distribution or main merge.

Candidate implementation: effective attendance view retains original raw clock events and append-only corrections. Single-open and monotonic clock-in checks use effective history. Manager review matches effective dates and raw clock evidence; recovered raw open sessions match raw clock-in date only, not every future date. UTC input uses second precision. Audit rollback, concurrent decision and raw mutation tests added. No payroll changes. Full Windows and desktop acceptance pending.
