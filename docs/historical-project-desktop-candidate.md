# Historical Project Register — desktop candidate

The archive has its own navigation and modal read-only register; no changes to operational project selectors, start authorization, billing or native numbering. Search covers legacy ID, original number, title and site. The filter uses original client IDs; the selected record shows historical source labels and the mapped native client ID. Empty and inconsistent archive states are handled separately.

Access requires HistoricalProjects.View and Clients.View. Evidence references are removed by the service for callers lacking full historical import authorization; hiding UI fields is not the permission boundary. The window rechecks authorization on activation and periodically (20 seconds); a denied or failed check clears displayed data. This polling is not instantaneous revocation. Data already seen or copied cannot be recalled.

Import review is available only in the synthetic acceptance workspace and only to the authorized import administrator. This workspace restriction is a UI guard, not a claim of source authenticity or a replacement for service authorization. Three distinct reviewed JSON files and independently retained lowercase source, CRM, project and census SHA-256 values are required. The exact bounded byte snapshots used by preview are retained for commit; file or hash selection changes invalidate the review, clear previous confirmation and note, and require preview again. A reviewed note and explicit confirmation are required. Only a ReadyForExplicitReview target enables commit. The service independently repeats validation and permissions inside its transaction. No success is assumed after exceptions. Neither source-reported Active status nor an Approved evidence label authorizes operational work.
