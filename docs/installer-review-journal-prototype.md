# Synthetic durable installation review journal

Source-only disposable SQLite prototype, not an installer. It has no production entry point or filesystem pointer operations. It persists at most five append-only review phases, binding exact plan and canonical observation bytes to a SHA-256 chain. Each append uses BEGIN IMMEDIATE and compares the independently retained checkpoint inside the transaction, replays all model transitions, writes one entry, reads it back, and commits. Reopening after a lost commit receipt, truncation, wrong plan, damaged record or stale checkpoint fails closed. No automatic reconciliation of missing receipts; an independently reviewed procedure must decide how to retain the new checkpoint after a commit. SQLite transaction rollback and independent connection contention are exercised on newly created disposable test files. Tests request DELETE journaling and synchronous FULL; this does not establish Windows power-loss behavior, directory metadata durability, actual filesystem switches, installer locking or disk-full recovery. The checkpoint must be retained independently; a hash chain is not a signature or tamper-proof evidence when both journal and checkpoint are controlled by an attacker. No actual business database or application payload is accepted by the harness. No authorization to execute, install, roll back or delete data.

Eight new test methods cover full chain, lost receipt, injected SQL write failure, close-before-commit, append-only guards, damaged/truncated chain, wrong plan/observations and concurrent writers. Native application code and security hold are unchanged. CI verification pending.
