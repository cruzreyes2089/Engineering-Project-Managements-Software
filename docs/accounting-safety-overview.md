# Consolidated accounting safeguards view

The existing Posting safeguards desktop dialog now retrieves its legacy rehearsal, full-wire drafts, attempt history, lifecycle hold and profile/marker presence through one authorized SQLite read transaction rather than three separately timed service calls. It clears all prior counts before a refresh and fails closed if any required grant or read fails. Hold status takes precedence over uncertainty, which takes precedence over missing fixture configuration. Counts are local simulations only, not invoices, cash or receivables. Reserved and witnessed full-wire attempts are unresolved; legacy reserved intents are shown separately because no send has begun. No profile endpoint, key or raw financial data is returned. No network requests or database changes. Existing history and explicit hold action remain separate; there is no hold reset. Requires existing rehearsal, wire preparation/rehearsal and financial report grants. This deliberately does not wire synthetic correction models into real accounting or assert provider qualification.
