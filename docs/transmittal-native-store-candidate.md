# Native transmittal persistence candidate

The inactive native store now binds reviewed intent to exact stored production PDF bytes, current document versions at preparation and issue, authorization and eligibility callbacks, and atomic intent/manifest/preparation event/audit insertion. Subsequent events are append-only with exact predecessor and explicit evidence; delivery can attest already recorded issue after supersession. Exact retries return prior records; changed retries rejected. Event metadata digest binds operation, audit ID, intent identity and sequence to the core event digest. Historical reads verify original bytes, intent, event chain and paired audits. Synthetic tests use minimal database and callbacks, not actual project authorization; no public service, actual issue, delivery, sending, signature, recovery integration or migration. Global census for orphan audits and unsealed intents remains required, plus actual project conflict/start/QA gates, owner-defined sign-off evidence, full migration and desktop qualification. Reissue of an identical manifest/recipient/purpose as a separate intent is currently refused by uniqueness; future design must decide how to distinguish intentional resend. PDF header is not full validation or malware scan. Latest combined qualification pending.
