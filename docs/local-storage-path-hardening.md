# Local storage path hardening — schema 47 candidate

The existing desktop startup trusted the default store path and checked only final acceptance directories. Recovery destination checks used File.Exists/Directory.Exists and could miss sidecar directories or redirected ancestors. Add a shared Core path policy for desktop development/acceptance startup, recovery creation and isolated restore. Reject non-fully-qualified paths, Windows network/device/nonfixed-drive paths, alternate streams, dot traversal, reserved device names and trailing dots/spaces. Walk existing ancestors before creating missing workspace directories, reject reparse points and wrong entry types, reject orphan sidecars for new database and all sidecars for closed recovery input/new output. Recheck staging and target just before exclusive publication. Ordinary existing live SQLite sidecar regular files remain supported at startup. No production workspace, data migration, schema change or release activation. Default development path remains the same; directory creation now occurs after validation in workspace resolution.

Tests exercise invalid paths, unsupported production startup, orphan/directory sidecars, recovery input/output refusal and conditional redirected-ancestor creation if supported by the runner. A skipped symlink creation case is not a pass. These are point-in-time checks for a trusted local filesystem, not race-free handle validation, hardlink identification, filesystem ACL enforcement, encryption or protection against a malicious process with profile access. Direct LocalPractice constructors and other export/import paths are not comprehensively hardened by this change. Recovery cleanup and publication still depend on a trusted private directory. Independent review and clean-machine acceptance remain mandatory. No actual data or executable distribution. Windows compilation/regression pending.
