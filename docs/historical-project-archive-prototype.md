# Sealed historical project archive — SQL prototype

This is an isolated relational design candidate, not a LocalPractice schema migration. Schema remains 46. Do not execute the prototype against an application database. The archive depends on the existing CRM migration batch and client-map relationship. The historical batch stores independent source, CRM transfer, project transfer and census digests; it checks the CRM transfer digest against the imported native CRM batch, whose hash is stored in uppercase. Hashes do not authenticate the actual source.

One nonempty historical batch (1–10000 records) is supported in the candidate; a successful zero-row preflight does not warrant a native archive import. Retain exact legacy project numbers even when duplicated, case-insensitively unique original project IDs, original parent identity and source-reported lifecycle/authorization strings. The prototype projects only sealed rows and a constant work_authorized=0. It does not create a native project, increment operational numbering, or imply verified authorization.

Insertion guards reject mismatched CRM provenance, orphan clients, duplicate identities, excess rows and premature sealing. Update/delete triggers protect historical tables, and explicit insert checks block replacement of existing batches, rows and seals even when recursive triggers are disabled. The service must later enforce complete package validation, required permissions, exact hashes, audit history, explicit confirmation, and one immediate transaction for batch, rows, seal and audit. A direct database writer with DDL access can defeat triggers; these are integrity controls, not security boundaries. SQL constraints supplement, not replace, full source text validation. The prototype permits partial unsealed rows if a caller commits improperly; native service integration must prevent that, and must fail closed on incomplete archive state. No archive-to-native project link, read permission, WPF register or migration service exists yet.
