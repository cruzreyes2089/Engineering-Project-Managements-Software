ASCII key restriction is intentionally narrower than the native review policy and must be reconciled before integration. SQL does not resolve paths, prove local folder identity, validate approved root revisions or establish access. Future native service must validate root, relative path and actual folder, restrict aliases and reparse points, prevent workspace overlap, bind exact root evidence and canonical key, verify access and actor inside immediate transaction; no open or enumerate by default.

Transmittal intent, immutable document manifest and append-only event history. Preparation seals manifest count; issue rechecks exact current eligible document metadata, delivery requires recorded issue and may attest historical delivery after document supersession; withdrawal is terminal and does not reverse delivery. Structural checks do not prove byte hashes, actual receipt, timestamps, actor authorization, professional sign-off or evidence authenticity. Native canonical model must bind record metadata, operation identities, and exact review evidence; duplicate operation rejection is not yet successful idempotent replay. A single transaction must insert intent, manifest and preparation event plus audit, verify read-back and rollback failures. SQL itself cannot prevent an intentionally committed unsealed intent or independently detect removal of an entire history with corresponding audits. Future global verifier must reject unsealed intents, orphan audits, metadata/digest discrepancies and wrong schema; recovery and migration must reconcile exact history. No real data, external folder access, transmission, actual issuance or release. Tests are synthetic minimal schema, not native qualification.
